v1.10.0では総合ホームに「世界史復習カレンダー」「定着度ダッシュボード」を追加しました。既存の文化史・年号の一問一答履歴から読み取り専用で集計し、予定と実績を日本時間で表示します。年代整序は別集計とし、DB・バックアップ形式・教材は変更しません。[分類基準と検証](docs/LEARNING_INSIGHTS.md)を参照してください。

v1.9.1では年表の初期画面を「重要年号で流れをつかむ」に変更しました。既存460件から73の節目を8テーマに整理し、短いつなぎの説明と教材の出典を縦型で表示します。「全件の年表」で従来の地域別比較も利用できます。教材・履歴・DB形式は変更しません。

v1.9.0では年号エリアに「年代整序テスト」「インタラクティブ年表」を追加しました。既存の年号教材460件をそのまま利用し、整序成績は一問一答と別に保存します。年号DB v1→v2の追加移行、旧バックアップの復元に対応します。[機能とデータ保護](docs/YEAR_CHRONOLOGY.md)を参照してください。

v1.8.0では文化史ホームに「今日のおすすめ20問」「類似知識の識別演習」「文化史の関連図」を追加しました。通常カードの履歴を保ったまま、比較演習の混同履歴を独立して記録します。文化史DBはv3へ追加移行し、バックアップは旧形式v1の復元と新形式v2の書き出しに対応します。年号エリアは変更しません。

関係データは [culture-relations.json](public/culture-relations.json) で独立管理し、既存教材のIDと出典から確認した68関係・13比較セットを収録しています。全関係は暫定検証扱いです。公開JSONの取得に失敗しても保存済みの関係・教材で学習できます。

v1.7.0では文化史の地域・時代選択を大区分に整理しました。ヨーロッパの時代は古代／中世／ルネサンス・宗教改革／17〜18世紀／19世紀／20世紀以降の6個です。細かな元の教材タグは任意の詳細欄に残し、ID・教材・履歴を変更せずに集約しています。[分類と互換性](docs/CULTURE_SCOPE.md)を参照してください。

文化史と年号に独立した学習エリアを持つ、Android Chrome向けのPWAです。起動時は総合ホームで学習エリアを選びます。各エリアは専用ホーム・問題演習・一覧・学習履歴・復習管理の5画面で構成し、共通設定にそれぞれのバックアップ・復元を置きます。スマートフォンの操作を優先したUIです。

v1.6.0ではUIを分離し、文化史365項目・506カードと既存IDを維持しています。年号は0件のままです。DB名・履歴形式・教材配信JSONを維持し、文化史と年号の成績は混在しません。[画面と保存の設計](docs/AREA_SEPARATION.md)を参照してください。

公開先：[世界史文化史マスター](https://kiyotakalam-collab.github.io/-/)。**Google Sheets・ChatGPTの実データ連携、Android実機でのインストールは未検証です。** ユーザー提供の西洋文化史の写真計37枚に基づいて収録しています。すべての教材ページが揃ったわけではありません。難易度は暫定分類として扱い、大学別過去問の裏付けを別途確認します。

## 起動

Node.js 24とnpmを使用します。

```sh
npm ci
npm run dev
```

本番相当のオフライン機能は開発サーバーではなく、ビルド後のプレビューで確認します。

```sh
npm test
npm run build
npm run preview
```

ブラウザテストは `npm run build` 後に `npm run test:e2e` を実行します。Chromiumがない環境では先に `npx playwright install chromium` を実行してください。実施済みの結果と残る制限は [テスト結果](docs/TEST_RESULTS.md) に記録します。Sheetsへ初期教材を移すCSVは `npm run sheets:seed` で出力できます。


## 自動同期（Apps Script不要・2026年11月9日から）

Google Sheetsの差分マスターは [世界史文化史マスター｜追加・修正用データ](https://docs.google.com/spreadsheets/d/1RYkYvk82hqNEIgNGx-xd5B64byQbVaXw087-8F-C78U/edit)。ChatGPTは新規カード・修正の事実確認後、Google SheetsのKnowledge/Cardsへ書き込み、同じ差分内容を `public/catalog-delta.json` に追記・更新する。用語とカードの固定ID、各行のversion、全体のcatalog.versionを保持する。アプリは `https://raw.githubusercontent.com/kiyotakalam-collab/-/main/public/catalog-delta.json` を起動時・通信復帰時に取得する。アプリにURLを貼り付ける必要はない。

**制限:** Google Sheetsを人手で直接編集しただけではGitHubへ同期されない。ユーザーがチャットで『文化史シートを反映』と伝えると、ChatGPTが両方を突き合わせて更新する。GitHubへ公開するのは検証済みの文化史カードだけで、端末内学習履歴・個人情報は公開しない。初回v12差分は `items: []`, `cards: []` なので既存365項目・506カードは消えない。アプリのソース変更は最初のv1.4.0配信のみで、以後のカード更新はJSONファイルだけで済む。


## 年号テスト（アプリv1.5.0から）

総合ホームから移動する専用の年号エリアを用意。**年号はユーザーが指定するまで登録しない**。初期公開教材 `public/year-events.json` は `items: []`（0件）である。

- 出題は出来事→年号のみ。答えを見て自己採点し、累積正答・累積誤答・連続正答・復習期限を記録。
- 絞り込み：レベルLv.1〜4、地域、時代、未学習・誤答履歴・復習期限、10問／20問／全問。
- 履歴：年号専用の独立したIndexedDB `world-history-year-test` に保存。文化史の `cultural-history-master` の回答履歴・カード数は一切変更しない。
- 年号履歴のJSONバックアップと復元は共通の「データ管理・設定」に専用のボタンを設置。文化史バックアップだけでは年号履歴を復元できないため、両方保存する。
- 年号データの管理：ChatGPTが指示された年号だけを根拠確認・重複チェック後に `public/year-events.json` へ追加。年号の追加にはアプリの再ビルドは不要。年号タブで公開版を自動取得し、端末に保存する。
- 年号の入力形式は整数年号に限定せず、紀元前・期間などユーザー指定の文字列を保持する。旧版の逆方向履歴がある場合もバックアップ・DBに保持する。

## 作者・作品の方向別演習と連続出題の抑制

文化史の「問題演習」には「出題の向き」を追加しました。

- 「全種類を混合」：人物・作品の両方向、業績、学説、画像などを含む従来の全カード
- 「作者・人物 → 作品」：既存の `person-work` カードだけ
- 「作品 → 作者・人物」：既存の `work-author` カードだけ

地域・時代・難易度・復習モードなどの条件と組み合わせられます。
従来の教材データに `context`・`achievement-person` として保存されている作者／作品カードも、項目の種類と問題文から方向を判定して対象に含めます。作者が特定できない作品や単に編纂を命じた人物の問題は原則除外し、カードIDや履歴・同期データの変更は不要です。
同じ答えを持つカードは、候補に別の答えがある限り離して配置します。
混合では同じ知識に関する表裏の連続も可能な限り避けます。
10問・20問指定時の通常モードは、対象カード全体から異なる答えを優先して選びます。
ただし「苦手優先」「復習期限到来」では従来の優先順位で対象枚数を先に確保します。
固定カードID・端末内の全回答履歴・累積誤答数は一切変更しません。

## 学習の流れ

1. ホームで学習状況を確認し、学習画面で範囲を選びます。
2. 問題を読み、タップして解答を表示します。
3. ○または×を選ぶと回答が端末に保存され、次のカードに進みます。
4. 復習期限到来・苦手優先・誤答履歴ありなどのモードで繰り返します。

地域・時代・分野・難易度・画像／文字を組み合わせて抽出できます。Lv.4の累積モードはLv.1〜4、単独モードはLv.4のみを対象にします。画像が表示できない場合は代替問題文で学習できます。

Lv.1〜3は著作→人物名、人物名→著作、学説→人物などの短い一問一答です。複数の知識を手がかりにする問題はLv.4に置きます。難易度の判定基準は用語の細かさ・重要度で、長い問題文自体を難易度の根拠にはしません。

レベル選択は各レベルの対象・カード数が見える選択式です。「選択レベルまで」と「選択レベルのみ」の対象範囲を具体的に表示します。アプリ1.4.0／同梱教材v11では、提供写真37枚までの内容を整理し、合計365項目・506カードです（うち画像カード72枚）。最終の写真2枚から31項目・37カードを追加しました。西洋文化史の提供範囲はここでいったん完了です。さらに既存の作品・建築物について、Wikimedia Commonsの個別ファイル情報と美術館の所蔵情報を確認して24画像と画像カード56枚を追加しました。撮影者の表示が必要な画像にはライセンスを記載しています。史実の外部資料との照合が済んでいない項目は暫定扱いです。

更新通知が出たら「データ管理 → 新しいバージョンに更新」を選びます。旧版の教材を使っている端末は、次の起動時に教材v11へ更新し、回答履歴を引き継ぎます。Sheets等からv11以上の独自マスターを取得済みの端末では、同梱教材で上書きしません。

## 履歴を守る仕組み

- `KnowledgeItem`（用語）、`Card`（問題）、`ReviewEvent`（回答履歴）に別々の固定IDを持たせます。表示名・説明・難易度の変更でIDを作り直しません。
- 正誤回数・連続正答・正答率・復習日時は、追記された回答履歴から算出します。正答しても過去の誤答は減りません。履歴を初期化する操作は用意していません。
- 用語マスターと端末内の履歴は別に保存します。同期は検証したマスターだけをトランザクションで更新し、同期失敗時には既存データを保持します。
- 表記揺れを正規化して名前・別名を比較します。正規化で判断できない同一人物・同一作品は、資料確認のうえ既存IDを再利用します。
- 削除は `deleted: true` による非表示です。レコードと履歴は保持します。取得データから行が消えただけでは削除しません。
- JSONバックアップには用語・カード・全回答履歴・設定を含めます。復元は履歴IDで重複排除して統合し、現在ある履歴を消しません。古いバックアップが新しい用語を巻き戻さないようにします。

ブラウザのデータ削除や端末故障からは端末内保存だけで復旧できません。学習後や端末変更前にJSONを書き出し、端末外にも保管してください。同じブラウザでも公開元のドメインやポートが変わると別の保存領域になるため、移行前のバックアップが必要です。

## 復習方式

誤答は短い間隔で再復習し、連続正答に応じて間隔を伸ばします。苦手優先は直近の誤答率・復習期限超過・最終学習日・連続正答を重視し、累積誤答数は補助要素にします。これは学習支援用の規則であり、大学別の出題予測ではありません。

## 構成

| 場所 | 役割 |
| --- | --- |
| `src/types.ts` | バージョン付き用語・カード・履歴の型 |
| `src/core.ts` | 実行時検証、重複検出、復習計算、範囲抽出 |
| `src/db.ts` | IndexedDB、履歴追記、バックアップ、マイグレーション |
| `src/seed*.ts` | 初期データとユーザー提供写真から作った追加カード |
| `src/sync.ts` | 公開JSONマスターの取得と安全な反映 |
| `src/pwa.ts`, `public/sw.js` | Service Worker登録、オフライン、更新待機 |
| `public/catalog-delta.json` | ChatGPTがSheetsと同時に更新する公開差分データ（v12〜） |
| `apps-script/` | 以前の代替同期方式（現在の初期設定には不要） |
| `sheets/` | Sheetsの列テンプレート |
| `.github/workflows/pages.yml` | テスト、ビルド、GitHub Pages公開 |

軽量なVite・TypeScript・標準DOM・IndexedDBを使用します。用語の追加はUIコードの変更を必要としません。カタログはメモリ上のMapで照合し、履歴はIndexedDBで永続化します。5,000〜10,000項目の拡張を前提にしていますが、実端末上の大量データ性能は別途確認が必要です。

## 画像問題と難易度の運用（教材v11）

- 画像カードは作品名・作者名・建築様式などを画像から答えられるよう複数方向に設定しています。画像の作品同定とライセンスはそれぞれの知識項目にある出典リンクを参照してください。
- 教材v11で用語の珍しさを基準に一部難易度を見直しました。Lv.1〜4は単語の細かさを示し、設問の複雑さとは別です。
- 2026年度の大学別過去問を網羅的に照合したわけではないため、難易度の調整はすべて暫定です。レベル配分を均等にする目的で一律に昇格させたものではありません。
- 写真や絵画の画像表示にはWikimedia Commonsの公開ファイルURLを使用しています。ネットワークが切れている端末では未取得画像が表示されない場合があります。その際は代替の文字問題が出ます。

## アプリ更新が届かない場合（v1.3.0以降）

1. GitHubリポジトリの `Settings → Pages → Build and deployment → Source` が **GitHub Actions** になっていることを確認する。
2. [Actions](https://github.com/kiyotakalam-collab/-/actions/workflows/pages.yml) の最新の **Test and deploy GitHub Pages** が成功し、deploy が完了していることを確認する。GitHubにコミットが保存されてもPagesの公開成功とは限らない。
3. Androidのアプリを開き、**データ管理 → 最新版を確認する**。新しいService Workerの待機が検出されたら、**新しいバージョンに更新**をタップする。
4. **同梱教材v11・アプリ1.4.0** が最新。公開JSONを取得した端末では **教材v12・365項目・506カード** となる。初期差分は空なので既存用語・問題を変更しない。
5. Chromeの通常タブで公開URLを開き直す。Chromeのシークレットモードでのみ新しく見える場合は端末内のService Workerが古い可能性がある。**保存データの削除やアプリのアンインストールは、履歴のバックアップを取るまで行わない**。

公開処理は単体テストとビルドが成功した場合のみ進む。ブラウザテストは失敗を記録するが、ネットワーク由来のテスト不安定性によって新しい教材の配信が永続的に止まることを防ぐため、公開の必須条件から外した。
