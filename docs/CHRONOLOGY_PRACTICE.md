# 通史誤答ノートの演習（v1.15.0）

## 操作

- 誤答一覧は問いだけを表示。用語名そのものが答えになるため、登録用語名も初期表示しない。個別演習、チェックした問題の演習に対応する。
- 地域・時代・原因・定着度・キーワード・出典・端末登録日を組み合わせる。一覧から演習を終えたら「元の一覧に戻る」で条件とスクロール位置を復元する。ブラウザバックと再読み込みにも対応する。
- 今日の復習：既存の `nextReviewAt` が現在以前の問題のみ。
- 苦手集中：累積誤答だけでは決めず、直近10回答の非正答率・連続誤答・再失点を重視。累積誤答の加点には上限がある。詳細な旧履歴は推測しない。
- ランダム・範囲指定：有効な登録済み問題から重複なしで選択。5・10・20・全問。設定でシャッフル可能。
- 1画面1問。「答えを見る」後に○正解／×不正解／△曖昧を採点する。曖昧は独立した回数で、正答・誤答を増やさず、連続正答を止めて10分後に再確認する。
- 前後移動で再表示しても同じ演習内では二重採点しない。未回答のまま移動・途中保存・終了しても誤答にならない。再度採点したい場合は新しい再演習を開始する。
- 未回答のシャッフルは、元の演習結果を部分保存して未回答だけで新しい演習を始める。回答済みの履歴を変更しない。
- 結果に今回の誤答、曖昧、連続誤答、復習予定、未回答数を表示し、それぞれを再演習できる。

## 保存と互換性

既存キー `world-history-chronology-errors-v1` とバックアップの `version:1` を維持する。新しい任意項目として `practiceEvents`, `practiceSessions`, `activePracticeId` を追加する。既存の正誤回数、最終学習日時、復習予定は移行時に変更しない。詳細履歴が存在しなかった時期の回答イベントは生成しない。

各回答は `sessionId + ':' + noteId` を固定回答IDとし、モード・正解／誤答／曖昧・回答日時・採点前の復習期限を追記する。各セッションは固定問題IDの順序、位置、開始・終了日時を保持する。学習成績の正本は引き続き各問題の累積回数であり、新イベントが既存回数に含まれることを検証する。

復元は回答IDで追加統合する。同じ回答IDの異なる内容は拒否。旧累積回数を基礎値として保持し、新しい重複しない回答だけを合算する。別端末で先に教材同期をしていても、初回取得日時を実際の最終演習日時と取り違えず、復習予定・登録日を保持する。旧形式のバックアップを新アプリで復元可能。旧アプリで新バックアップを処理して新履歴を保持できることまでは保証しない。

Google Sheetsの配信は既存の方式を維持する。同期はマスター列のみ更新し、演習履歴・途中の問題順を保持する。演習画面で更新を受信したら検証し、終了後に反映する。新しい配信問題は0回答・未演習であり、登録で誤答を加算しない。他エリアのDBにはアクセスしない。

## 定着度

- 未演習：回答0回。
- 再判定待ち：旧累積回数はあるが、新形式の詳細回答履歴がない。
- 定着初期：新形式の連続正答が3回未満。誤答・曖昧は連続正答を止める。
- 定着途中：連続3正答以上だが、安定の間隔条件を満たさない。
- 安定：現在の連続正答が3回以上、その連続正答が7日以上にわたり、期限到来後の正答を2回以上含む。

同日繰り返すだけで安定にならない。期限超過だけを理由に定着度を下げない。連続正答数は実際に記録した新形式の履歴から算出し、旧履歴の未記録部分は不明として表示する。誤答後の通常の復習間隔は既存方式（正答1→3→7→14→30日、不正解10分）を再利用する。

## 将来の「1知識・複数の問い」

既存93問のJSONと固定IDは変更しない。今後、同じ知識の基本・識別・関連問題を登録する場合、配信の各問題に次の任意項目を付ける。

| 項目 | 型・意味 |
|---|---|
| `knowledge_id` | 固定知識ID。同一知識の別の問いで共用。設定後は変更しない |
| `question_type` | `basic` / `distinction` / `related` |
| `verification` | `verified` / `provisional` |
| `verification_sources` | `[{"title":"確認資料名","url":"https://…"}]`。URL省略可、検証済みには資料名必須 |

問いごとの `id` は別々の固定IDで、成績も個別に保持する。新しい関連付けや問い種別を付けるときは検証状態が必要。`provisional` は出題対象外。`verified` は根拠資料が必要。既存の `source` / `source_detail` はユーザーが誤答した問題集などの出典であり、史実確認資料と混同しない。既存の配信版・署名・Sheets12列の仕様は維持し、任意項目を使う更新では教材バージョンを増やす。

アプリは別角度の問題文・正解・史実を自動生成しない。ChatGPT等が検証して配信した問題だけを利用する。今回、教材の追加・修正は行っていない。
